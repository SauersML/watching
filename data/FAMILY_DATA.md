# Question-family grouping and new context evaluations

The version-1 family experiment uses the existing 1,024 training contexts and the separately documented [question bank](QUESTION_FAMILIES.md). It changes question structure while assigning **each training context to exactly one training question family**. Both numerical conditions receive the identical rendered prompt. Condition labels and grouping metadata never enter the prompt.

`new_contexts_v1.jsonl` contains 128 newly AI-authored contexts: eight examples in each of 16 familiar training content families. `ood_contexts_v1.jsonl` contains 128 newly AI-authored contexts: 32 each in bilingual glosses, ASCII spatial layouts, editorial revision markup, and musical notation. These structures are absent as named families from the training collection. The sentences and diagrams were written individually rather than generated by substituting nouns or numbers. They are not human conversation samples. Familiar family membership does not establish identically distributed sampling; exact deduplication does not establish semantic independence.

The new context collections have no normalized exact duplicates within either file, between the files, or against the earlier training, validation, test, and fresh-test context collections. The builder rejects overlap after case, punctuation, and whitespace normalization. It also checks the original expanded synthetic and diverse context banks. Existing training IDs are preserved; new IDs derive from a hash of normalized context text.

## Splits and roles

| Split | Contexts | Question families | Role |
|---|---:|---|---|
| `train` | Existing 1,024 | 12 training families, four phrases each | Grouped cross-validation and final fitting |
| `validation` | Previously inspected 64 | Training families | Development reporting only; no hyperparameter selection |
| `test` | New 128 from familiar content families | Training families | New-context evaluation |
| `test_wording` | The same new 128 | Four unseen question families | Paired wording transfer |
| `ood_context` | New 128 structural contexts | Training families | Context-structure transfer |
| `ood` | The same 128 structural contexts | Four unseen question families | Combined context and wording transfer |

`test` and `test_wording` are a paired comparison, not independent cohorts. The same is true of `ood_context` and `ood`. These four cells separate changes in context structure from changes in question structure. The two new context collections are distinct; no final-evaluation context is fitted.

Every row includes `context_id`, content `family`, `question_family`, `wording_id`, `selection_group`, and `data_role`. Training `selection_group` equals the question-family identity. The 12 groups have 85 or 86 contexts each, with content families distributed across groups. Phrase variants are balanced within each question family. Assignments are deterministic and identical across probe, execution, and preference tasks. Non-training rows have a null selection group.

The reporting `validation` split deliberately reuses previously inspected contexts, so it is **not fresh evidence**. The runner must honor grouped training-only selection; merely supplying this dataset to a validation-selecting runner would not implement that protocol. The final context files were authored after earlier experiments and must not be used for selecting the current edit. Any future adjustments informed by their results would make those results development evidence for the adjusted experiment.

For uncertainty estimates, condition pairs belong to the same prompt. Question families and content families are additional shared sources of dependence. In particular, the OOD set crosses only four content families with four question families; many prompts do not create many independent families. Report which units are resampled rather than claiming assumption-free inference.

## Reproduce

From the repository root:

```sh
PYTHONPATH=src python -m watching.family_data \
  --task probe \
  --contexts data/training_contexts_a.jsonl data/training_contexts_b.jsonl \
  --question-bank data/question_families_v1.jsonl \
  --new-contexts data/new_contexts_v1.jsonl \
  --ood-contexts data/ood_contexts_v1.jsonl \
  --tokenizer Qwen/Qwen3-8B --max-length 96 \
  --out /tmp/watching-family-probe.json
```

Use `execution` or `preference` for the other tasks. The default prior-context exclusion file is `data/fresh_test_contexts.jsonl`; additional earlier collections can be supplied with `--prior-contexts`. The builder rejects overlong rendered prompts rather than truncating them.

At creation, the longest assigned Qwen3-8B chat prompts were **66 tokens for probe, 63 for execution, and 61 for preference**, below the chosen fixed length of 96. These are tokenizer checks on the assigned combinations, not measurements of model behavior. Runtime must check its own tokenizer as well. The test suite checks group balance, cross-task assignment parity, exact split separation, intentionally paired contexts, old-context rejection, question-bank integrity, and hard failure on overlong inputs.
